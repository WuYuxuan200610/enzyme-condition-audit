# 金标签评测报告 —— 条件抽取 vs 人工标注

> 用**独立人工标注金集**（JackKuo，非自建）评测条件抽取器。这是本项目第一次不依赖自造代理指标的评测。
>
> **结论**：抽取器**召回极高**（pH 98.0%、温度 97.3%、缓冲液 100%），说明"能不能找到条件"已基本解决；
> **真正的难点转为"消歧"**（区分测定条件 vs 纯化/储存/培养条件）——这由宽口径下的低精确率（pH 47.7%）直接体现。

---

## 1. 设计

| 项 | 内容 |
|---|---|
| 金集 | [JackKuo 酶动力学金集](https://huggingface.co/datasets/jackkuo/LLM-Enzyme-Kinetics-Golden-Benchmark)（4,244 条人工标注，156 篇论文） |
| 输入 | 从金集 PMID 中筛出**有开放获取全文**者，抓取 Europe PMC 全文（37 篇，[prepare_gold_eval.py](../benchmark/prepare_gold_eval.py)） |
| 金标签 | 每篇论文人工记录的 pH / 温度值集合 + 条件串（[build_gold_reference.py](../benchmark/build_gold_reference.py)） |
| 抽取 | LLM 对全文**宽口径**列出所有 pH / 温度 / 缓冲体系 / 盐（workflow 并行 8 批） |
| 评测 | 值级召回（容差 0.05）+ 论文级精确（[eval_against_gold.py](../benchmark/eval_against_gold.py)） |

**口径说明**：抽取被要求"列出全文中所有出现的 pH/温度"，而金集是"测定条件"口径。
因此抽取集应为金集的**超集**——**召回是主指标，精确率偏低属预期**，其含义见第 3 节。

---

## 2. 结果

### 2.1 召回（核心指标）

| 维度 | 值级召回 | 论文级平均召回 |
|---|---|---|
| **pH** | **50 / 51 = 98.0%** | 99.0%（33 篇有 pH 金标） |
| **温度** | **36 / 37 = 97.3%** | 98.9%（30 篇有温度金标） |
| **缓冲液体系** | — | **23 / 23 篇 = 100%** |

### 2.2 精确率（宽口径）

| 维度 | 论文级平均精确 |
|---|---|
| pH | 47.7% |
| 温度 | 39.1% |

### 2.3 漏抽明细（仅 2 处，同一篇）

| 论文 | 漏抽项 | 可能原因 |
|---|---|---|
| PMC4323659（VmoLac 漆酶） | pH 6.5 | 很可能位于表格/图中，转纯文本时丢失 |
| PMC4323659（同上） | 40 °C | 同上 |

**除这一篇外，37 篇全部召回 100%。**

---

## 3. 结果怎么解读（关键）

低精确率**不是抽取错误**，而是任务口径造成的：

- 抽取器被要求"列出全文所有 pH"，于是它忠实列出了：测定 pH（7.5）、**纯化缓冲液 pH**（7.9）、**储存 pH**、**pH-活性曲线的每个扫描点**（如 6.03–10.50 共 16 个值）；
- 金集只记"该条动力学数据的测定 pH"（如仅 7.5）。

所以精确率低反映的是**没做消歧**，而非抽错值。举例（PMC4334965）：

```
金集 pH:     [7.5]
抽取 pH:     [6.0, 6.03, 6.55, 6.67, 7.08, 7.46, 7.5, 7.73, 8.29, 8.5, 8.55, 8.89, 8.94, 9.68, 9.93, 10.5]
             └─ 其中 7.5 命中；其余是 pH-活性曲线的实测点（本身是真实且有用的信息）
```

**这直接指明了下一步**：

> 从"能不能找到条件"（已解决，召回 ~98%）
> → 转向"**哪个 pH 属于哪条动力学数值**"（消歧与配对，尚未解决）。

---

## 4. 诚实局限

1. **样本量**：37 篇、pH 金标 51 个值、温度 37 个值。**召回率置信区间较宽**（1 个漏抽就影响约 2 个百分点）。
2. **金集本身可能有噪声**：金集的 `Cosubstrate` 列绝大多数填的是辅因子（ATP/NADH 等），只有约 7% 含缓冲液——因此"缓冲液 100%"这一项是**基于金集中确实出现缓冲液串的 23 篇**，口径较宽。
3. **全文来自 Europe PMC XML**，表格内容可能已丢失（漏抽的 2 处很可能是此类），故 98% 是**偏保守**的估计。
4. **精确率不可直接当"错误率"**：如第 3 节所述，它是口径差异的产物。
5. **未做值-记录级配对**：本评测是"值集合"级别，不判断"这条 pH 属于哪条 kcat"。

---

## 5. 对项目的意义

| 问题 | 之前的状态 | 现在 |
|---|---|---|
| 条件抽取行不行？ | 只有 16 条正例的自造代理（precision 75%） | **37 篇独立人工金标，召回 98.0%（pH）/ 97.3%（温度）/ 缓冲液 100%** |
| 缺口是否真实？ | 自建正则代理 | **人工真值证实**：EnzyExtract 对 pH/温度漏 21–24%，缓冲液 0% |
| 真正的难点？ | 一度误判为"报告率低"（实为采样偏差） | **消歧 + 值-记录配对**（精确率低所暴露的核心问题） |

**下一步的明确目标**：给定一篇论文，输出 `[(kcat/Km 数值, 该数值对应的测定条件)]` 配对列表。
这是 EnzyExtract `solution=0%` 的根因，也是本工具唯一还没攻下的关卡。

## 6. 复现

```bash
python benchmark/prepare_gold_eval.py     # 抓金集论文开放获取全文（需联网）
python benchmark/build_gold_reference.py  # 建金集参考答案
# 抽取：见本次 workflow（8 批 → gold_eval/extract_*.json）
python benchmark/eval_against_gold.py     # 评测
```

产出：`gold_eval/gold_reference.json`、`extract_*.json`、`eval_summary.json`。
